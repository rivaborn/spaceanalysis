# Efficient disk-space analysis script (PowerShell)

Task: Lets write a script to  review  disk space use on this system and recommend ways to free up
space. Attempting to read every file and folder will take hours and be very inefficienct. Lets use a
more efficient methodology for the analysis.

- [ ] Step 1: Create analyze-disk.ps1 with a param block (-Root default C:\, -Top default 20, -Output optional) and a read-only core size helper (>Get-DirSize) that computes a directory's recursive total in ONE pass using metadata-only enumeration (Get-ChildItem -File -Recurse | Measure-Object Length), returning 0 for missing/inaccessible paths. Print a ranked 'Top space consumers under Root' table of the direct child directories sorted by total size descending, plus the root's grand total. Script is strictly read-only; it never opens file contents and performs no deletion. ASSUMPTION: 'efficient methodology' means metadata-only single-pass enumeration (fast) rather than reading every file's contents, and drill-down into the biggest consumers rather than a full exhaustive scan.
  - files: analyze-disk.ps1
  - verification: In Git Bash: create a temp fixture with known sizes (a dir containing a ~5 MB file plus a small file, and another small dir), then run `powershell -NoProfile -ExecutionPolicy Bypass -File analyze-disk.ps1 -Root <spaceanalysis>`. Success: output is a ranked table and 'Total:' reflects ~5 MB; the fixture dir is ranked first above sibling dirs. Then delete the fixture.
- [ ] Step 2: Add a drill-down walk (>Expand-Top) to analyze-disk.ps1: after ranking the root's direct children, for each of the Top N consumers recursively descend up to a configurable -Depth (default 2) levels, printing each level's children sorted by size, so it reveals which subdirectories drive the top consumers without scanning the whole tree exhaustively. Only the top N branches are expanded, keeping runtime bounded.
  - files: analyze-disk.ps1
  - verification: In Git Bash, create a nested fixture (dir -> bigdir -> subdir with a ~3 MB file, plus a small sibling), run the script with -Root pointing at the nested fixture and -Depth 2. Success: the biggest dir is ranked first, its child containing the 3 MB file is expanded one level under it, and it does not descend further than the configured depth. Then delete the fixture.
- [ ] Step 3: Add a cleanup-recommendation section (>Find-CleanupCandidates) to analyze-disk.ps1: scan well-known Windows waste locations (current-user TEMP, C:\Windows\Temp, Recycle Bin C:\$Recycle.Bin, Windows Update download cache, Windows Installer, user package caches for pip/npm/nuget where present) and print each found location with its reclaimable size and a suggested safe cleanup command hint, plus explicit wording that the script itself performs no deletion. Missing locations are reported as 'not present' and skipped.
  - files: analyze-disk.ps1
  - verification: Run the script with -Root C:\. Success: a 'Cleanup candidates' section lists TEMP and Recycle Bin entries each with a size and a Remove-Item hint, missing probed paths are labeled 'not present', and no files are deleted by the run (pre-existing fixture files still exist after the run).
- [ ] Step 4: Polish the report output so the script prints one cohesive markdown report (System summary, Top consumers, Drill-down, Cleanup candidates) and writes it to the -Output file when given. Add a short parameter usage/help text when run with -Help. Create/update README.md documenting what the script does, the efficient methodology (metadata-only enumeration, top-down drill into largest consumers, bounded depth), usage examples, and the safety note that it only reports and never deletes.
  - files: analyze-disk.ps1, README.md
  - verification: Run the script with -Root C:\ -Output <repo>/report.md, then grep report.md for the section headings and check README.md mentions spaceanalysis. Success: report.md contains all four report sections and README.md documents usage, methodology and the safety note.
